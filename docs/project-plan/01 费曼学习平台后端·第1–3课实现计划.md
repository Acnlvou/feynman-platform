## 五、逐文件实现要点

### `index.js`（三课演进，最终形态）

1. 引入 `express` / `mongoose` / `cors` / `dotenv`，`dotenv.config()`。
2. 中间件：`app.use(cors())`、`app.use(express.json())`。
3. 第 1 课遗留路由：`GET /` → `Hello, Feynman Learner!`（保留讲义原文，用于验证服务已起）。
4. 第 3 课引入的路由：`app.use('/api/users', require('./routes/users'))`、`app.use('/api/knowledge-points', require('./routes/knowledgePoints'))`。
5. 数据库连接：`mongoose.connect(process.env.MONGO_URI)`；**连接失败只告警不崩溃**（`catch` 里 `console.error`），并配置 `bufferCommands:false` 让数据库操作快速失败而非挂起。
6. 启动自检：`JWT_SECRET` 缺失时打印醒目告警（不阻断启动，便于无库调试）。
7. 在路由之后挂载 `errorHandler`。
8. `app.listen(process.env.PORT || 3000)`，打印监听地址。

### `models/User.js`（第 2 课）

`username`(String, required, unique)、`email`(String, required, unique)、`password`(String, required)，`{ timestamps: true }`。

→ 字段名统一为 `username`（修正第 3 课误用的 `name`）。

### `models/KnowledgePoint.js`（第 3 课）

`user`(ObjectId, ref User)、`title`(String, required)、`content`(String, required)、`status`(String, enum `['not_started','in_progress','mastered']`, default `'not_started'`)、`reviewList`(Boolean, default false)，`{ timestamps: true }`。

→ 讲义注释里写了枚举但代码没加 enum，本次**补上 enum 约束**。

### `routes/users.js`（第 3 课）

- `POST /register`：解构 `{ username, email, password }`；先按 `email` 与 `username` **都查重**（修正第 3 课只查 email）；bcrypt `genSalt(10)` + `hash`；保存后签发 JWT（`expiresIn: process.env.JWT_EXPIRE || '5h'`）并返回 token（注册即登录，统一第 2/3 课差异）。
- `POST /login`：按 `email` 查用户，`bcrypt.compare` 校验，签发并返回 token；失败统一返回「邮箱或密码错误」。
- 路由挂载于 `/api/users`，故完整路径为 `/api/users/register`、`/api/users/login`（统一第 2 课的 `/api/register`）。

### `middleware/auth.js`（第 3 课）

读 `req.header('x-auth-token')` → 无 token 返回 401；`jwt.verify(token, process.env.JWT_SECRET)` 失败返回 401；成功则 `req.user = decoded.user` 后 `next()`。

→ 认证头**统一为 `x-auth-token`**（修正第 3 课 Postman 演示误用 Bearer/Authorization）。

### `routes/knowledgePoints.js`（第 3 课）

全部挂 `auth` 中间件：

- `POST /`：创建，`user` 取自 `req.user.id`。
- `GET /`：`find({ user: req.user.id }).sort({ createdAt: -1 })`。
- `GET /:id`、`PUT /:id`、`DELETE /:id`：先查再校验归属（`kp.user.toString() !== req.user.id` → 401/404），只能操作自己的知识点。

→ 补全讲义留白的 `GET /:id`。

### `utils/response.js` + `middleware/errorHandler.js`（轻量工程化）

直接采用讲义第 2 课「进阶技巧」里的示例写法，保持课程血统一致：

- `createResponse(success, data, message, error)` → `{ success, data, message, error }`。
- `errorHandler`：捕获未处理错误与 404，统一返回 JSON；开发环境附带 `err.message`。
- **影响**：注册/登录等响应会从讲义的裸 `{ token }` 变为 `{ success, data:{ token }, message }` —— 该差异在 `docs/technical/backend-errata.md` 中明确标注。

## 七、验证方案（关键：当前没有数据库）

代码写完后，用以下步骤证明「工程是通的」，无需 Atlas：

1. **语法检查**：对每个 `.js` 执行 `node --check <file>`，全部无报错。
2. **启动服务**：`npm start` → 终端打印监听日志；若 `MONGO_URI` 无效，只打印连接失败**告警**，**服务照常运行**（不崩溃）。
3. **根路由**：`curl http://localhost:3000/` → `Hello, Feynman Learner!`（证明服务活着）。
4. **认证中间件可验证（不依赖数据库）**：`curl http://localhost:3000/api/knowledge-points`（不带 token）→ `401`，证明 `auth.js` 与路由已正确挂载。
5. **数据库未连接时的优雅降级**：`POST /api/users/register` → 返回统一格式的 `503/500` 错误（如「数据库未连接」），而不是长时间挂起或崩溃。
6. **拿到 Atlas 后**：填好 `.env` 的 `MONGO_URI` 重启，即可真实跑通「注册 → 登录 → 带 token 建知识点 → 查询/更新/删除」。

## 十、风险与注意

- **`JWT_SECRET` 缺失**：启动时告警，避免签发不可验证的 token。
- **Mongoose 未连接**：靠 `bufferCommands:false` + `errorHandler` 让接口快速返回明确错误，而不是卡住。
- **`.env` 泄漏**：只入库 `.env.example`；`.gitignore` 已忽略 `.env`（呼应压缩包分发需求）。
- **响应格式变化**：统一响应会让返回体结构与讲义不完全一致，已在 `docs/technical/backend-errata.md` 标明，供决定是否回改讲义。
