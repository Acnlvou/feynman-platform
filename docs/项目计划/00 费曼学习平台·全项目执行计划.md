## 1. 项目概述与愿景

### 1.1 项目定位

「费曼学习平台」是一个以**费曼学习法**（用最简单的语言把自己学会的知识讲清楚）为核心的智能学习工具。它把「输入知识 → 复述输出 → AI 反馈 → 针对性复习」的闭环产品化，并用可视化手段让知识之间形成网络。

一句话概括：**你负责讲，AI 负责听和批改，图谱负责把知识连起来。**

### 1.2 费曼学习法闭环（产品核心流程）

```
① 录入知识点                    ② 用自己的话复述（录音）
   Markdown / LaTeX / Mermaid       MediaRecorder 录音
        │                                 │
        ▼                                 ▼
⑥ 知识可视化  ◀──┐            ③ 语音转文字（ASR）
   2D 图谱 / 3D 宇宙 │                    │
        │           │                    ▼
        │      ⑤ 复习计划 ◀── ④ AI 润色 + 打分 + 评价
        │       SM-2 间隔重复      └─▶ 识别薄弱点
        └──────────  AI 智能出题 ◀───────┘
```

**闭环六步**：

1. **录入**：新建知识点，支持 Markdown / LaTeX / Mermaid 原文。
2. **复述**：对着知识点用自己的话讲解并录音。
3. **转写**：后端调用 ASR 把音频转成文字。
4. **评价**：LLM 润色复述文本、按理解程度打分、指出优点与薄弱点。
5. **出题与复习**：针对薄弱点 AI 出题，并自动加入间隔重复复习计划。
6. **可视化**：知识点之间以「前置/相关/依赖」关系连接成图谱，并提供 3D 知识宇宙视图。

### 1.3 目标用户与使用场景

| 用户 | 场景 | 价值 |
|---|---|---|
| 学生（主要） | 学完一节内容后自测掌握程度 | 立刻得到反馈，发现盲区 |
| 自学者 | 输入零散知识点，构建个人知识体系 | 知识不再孤立，形成网络 |
| 教师 | 布置「讲解知识点」作业 | 通过录音+AI 评分快速了解学情 |

### 1.4 学习成果目标

完成本项目后，学生应能独立完成：前后端分离的全栈应用开发、RESTful API 设计、数据库建模、JWT 认证、第三方 AI 服务集成、数据可视化、跨端打包与云端部署——即具备「大前端 + 全栈 + AI 应用」的完整工程能力。

## 2. 产品功能蓝图

### 2.1 功能模块总览

| 模块 | 功能点 | 优先级 |
|---|---|---|
| **用户系统** | 注册、登录、JWT 认证、获取当前用户 | MVP |

| **AI 出题** | 依薄弱点生成单选/填空/简答题 + 解析 | MVP |
| **复习计划** | 自动排期（简化 SM-2）、今日待复习、标记完成 | MVP |

| **3D 知识宇宙** | Three.js 升维视图、按掌握度着色、可旋转缩放 | 加分 |
| **跨端** | PWA（移动端 App 体验）、Electron 桌面端 | 加分 |
| **工程化** | Swagger API 文档、Jest 单元测试、统一响应/错误处理 | MVP |

### 2.2 MVP 边界（MoSCoW）

- **Must（必须做，答辩底线）**：用户系统、知识点 CRUD、录音 + ASR、AI 评价与出题、复习计划。
- **Should（应该做）**：Swagger 文档、Jest 测试、统一响应与错误处理。
- **Could（可以加分）**：2D 知识图谱、3D 知识宇宙、微调 UI 设计。
- **Won't（本期不做）**：多人协作、社区分享、付费体系、移动原生上架。

### 2.3 迭代原则

> 遵循讲义「渐进式开发、小步快跑」：每次迭代都应是**可编译、可运行、可测试**的独立单元，绝不留半成品。

**LLM 统一封装示例**（一套代码切换多家供应商）：

```js
// src/utils/llm.js（示意）
const OpenAI = require('openai');

const client = new OpenAI({
  apiKey: process.env.LLM_API_KEY,
  baseURL: process.env.LLM_BASE_URL, // 如 https://api.deepseek.com
});

// 润色 / 打分 / 出题 三个函数共用 client.chat.completions.create
async function chat(messages, opts = {}) {
  const res = await client.chat.completions.create({
    model: process.env.LLM_MODEL,
    messages,
    temperature: opts.temperature ?? 0.7,
  });
  return res.choices[0].message.content;
}

module.exports = { chat };
```

### 3.5 关键数据流（复述→评分闭环）

1. 前端 `POST /api/knowledge-points` 新建知识点（`auth` 中间件校验 JWT）。
2. 前端 `MediaRecorder` 录音 → `POST /api/recordings` 上传音频 → `POST /api/recordings/:id/transcribe` 触发 ASR，写入 `transcript`。
3. 前端 `POST /api/ai/evaluate`（携带 `kpId` + 复述文本）→ 后端组装 prompt 调 LLM → 写 `aievaluations` → 返回润色文本 + 评分 + 薄弱点，并回写 `KnowledgePoint.masteringScore`。
4. 前端 `POST /api/ai/generate-questions`（携带薄弱点）→ LLM 生成题目写 `questions`，并自动创建 `reviewplans`。
5. `GET /api/graph` 聚合 `knowledgepoints` + `kprelations` 返回 `{nodes, edges}`，前端分别用 G6 渲染 2D 图谱、Three.js 渲染 3D 知识宇宙。

## 4. 数据模型设计

> 命名沿用讲义（`users` / `knowledgepoints`），新增 5 个集合；全部使用 `{ timestamps: true }` 自动维护 `createdAt` / `updatedAt`。

### 4.1 User（用户）

```js
// src/models/User.js
{
  username:    { type: String, required: true, unique: true },
  email:       { type: String, required: true, unique: true },
  password:    { type: String, required: true },   // bcryptjs 哈希后存储
  displayName: { type: String },                    // 展示名（可选）
  avatarUrl:   { type: String },                    // 头像（可选）
}
```

**设计理由**：与讲义完全一致；`displayName` / `avatarUrl` 为前端展示预留。**密码绝不存明文**，注册时用 `bcrypt.genSalt(10)` + `bcrypt.hash` 处理。

### 4.2 KnowledgePoint（知识点）

```js
// src/models/KnowledgePoint.js
{
  user:           { type: ObjectId, ref: 'User', required: true, index: true },
  title:          { type: String, required: true },
  content:        { type: String, required: true },   // Markdown/LaTeX/Mermaid 原文
  status:         { type: String, enum: ['not_started', 'in_progress', 'mastered'], default: 'not_started' },
  reviewList:     { type: Boolean, default: false },
  tags:           { type: [String], default: [] },     // 标签，支撑检索与聚类
  masteringScore: { type: Number, min: 0, max: 100, default: 0 }, // 由 AI 评价聚合
  difficulty:     { type: Number, min: 1, max: 5 },    // 用户自评难度，喂给出题
}
```

**设计理由**：保留讲义字段（`user` / `title` / `content` / `status` / `reviewList`）；`tags` 支撑检索与图谱聚类；`masteringScore` 让前端按掌握度着色；`difficulty` 控制 AI 出题难度。

### 4.3 Recording（录音 / 转写记录）★新增

```js
// src/models/Recording.js
{
  user:        { type: ObjectId, ref: 'User', index: true },
  kp:          { type: ObjectId, ref: 'KnowledgePoint', required: true, index: true },
  audioUrl:    { type: String },                        // GridFS / 对象存储地址
  durationSec: { type: Number },
  status:      { type: String, enum: ['uploaded', 'transcribing', 'done', 'failed'], default: 'uploaded' },
  transcript:  { type: String },                        // ASR 转写结果
  asrProvider: { type: String, enum: ['tencent', 'ali', 'whisper_local'] },
  language:    { type: String, default: 'zh' },
}
```

**设计理由**：把「音频」与「文本」分离，便于重跑 ASR 与追溯来源；`status` 支撑异步转写的状态机。

### 4.4 AiEvaluation（AI 评价记录）★新增

```js
// src/models/AiEvaluation.js
{
  user:         { type: ObjectId, ref: 'User', index: true },
  kp:           { type: ObjectId, ref: 'KnowledgePoint', index: true },
  recording:    { type: ObjectId, ref: 'Recording' },
  score:        { type: Number, min: 0, max: 100 },
  level:        { type: String, enum: ['excellent', 'good', 'weak'] },
  polishedText: { type: String },                       // AI 润色后的复述文本
  comment:      { type: String },                       // 总体评语
  strengths:    { type: [String] },
  weaknesses:   { type: [String] },                     // 薄弱点 → 驱动出题
  model:        { type: String },                       // 使用的 LLM 标识
}
```

**设计理由**：每次 AI 评测结果可追溯；`weaknesses` 直接驱动下一环「AI 出题」；`score` 回写 `KnowledgePoint.masteringScore`。

### 4.5 Question（AI 生成题目）★新增

```js
// src/models/Question.js
{
  user:        { type: ObjectId, ref: 'User', index: true },
  kp:          { type: ObjectId, ref: 'KnowledgePoint', index: true },
  type:        { type: String, enum: ['single', 'fill', 'short'] }, // 单选/填空/简答
  stem:        { type: String, required: true },        // 题干
  options:     { type: [String] },                      // 单选的选项
  answer:      { type: String },
  explanation: { type: String },                        // 解析
  difficulty:  { type: Number, min: 1, max: 5 },
  generatedBy: { type: String },                        // 模型标识
}
```

**设计理由**：题目与知识点、用户绑定，支持错题复盘与复习计划引用。

### 4.6 ReviewPlan（复习计划，简化版 SM-2）★新增

```js
// src/models/ReviewPlan.js
{
  user:           { type: ObjectId, ref: 'User', index: true },
  kp:             { type: ObjectId, ref: 'KnowledgePoint' },
  question:       { type: ObjectId, ref: 'Question' },   // 关联题目（可选）
  dueDate:        { type: Date, index: true },
  intervalDays:   { type: Number, default: 1 },          // 间隔：1/3/7/15 天
  easeFactor:     { type: Number, default: 2.5 },        // SM-2 简易版
  lastReviewedAt: { type: Date },
  nextReviewAt:   { type: Date },
  status:         { type: String, enum: ['pending', 'done', 'skipped'], default: 'pending' },
}
```

**设计理由**：实现费曼流程第 5 步「加入复习计划」；用简化 SM-2 算法（答对则 `intervalDays *= easeFactor`，答错则重置为 1）自动排期。

### 4.7 KpRelation（知识图谱边）★新增

```js
// src/models/KpRelation.js
{
  user:   { type: ObjectId, ref: 'User', index: true },
  source: { type: ObjectId, ref: 'KnowledgePoint', index: true },
  target: { type: ObjectId, ref: 'KnowledgePoint', index: true },
  type:   { type: String, enum: ['prerequisite', 'related', 'dependence'] }, // 前置/相关/依赖
  weight: { type: Number, min: 0, max: 1, default: 0.5 },
}
```

**设计理由**：图谱的边集合；`/api/graph` 聚合知识点与关系后输出 G6 / Three.js 所需的 `nodes` / `edges`。可手动维护，也可由 LLM 依据知识点内容自动建议关联。

## 6. 开发规范与 AI 协作流程

> 本章直接承接讲义《附录：项目开发规则》，是团队协作与 AI 使用的强制约定。

### 6.1 基本开发原则

1. **语言规范**：所有交流、文档、代码注释统一使用**中文**。
2. **代码修改原则**：**只修改与当前任务相关的代码和文件，无关内容绝不触碰。**
3. **开发环境**：Windows / macOS 双平台，命令与工具需考虑兼容性。
4. **文档管理**：**文档先行**，功能变更必须同步更新开发与技术文档。

### 6.2 AI 辅助编程黄金法则

| 法则 | 含义 |
|---|---|
| 你是机长，AI 是副驾 | 你才是代码的最终负责人，采纳/修改/提交的决定权在你 |
| 永不轻信，务必验证 | AI 代码可能有错或有安全漏洞，必须审查、理解并测试 |
| 垃圾输入，垃圾输出 | Prompt 越清晰具体，产出质量越高 |
| 用于学习，而非作弊 | 让 AI 解释代码，把它当 24 小时老师 |
| 遵守规范，聚焦问题 | 只改与问题相关的代码 |
| 文档先行，持续同步 | 先生成/更新文档，再写代码 |

### 6.3 高效人机协作开发流程（七步法）

1. **需求定义** → 2. **审核与修订** → 3. **任务分解**（产出功能开发计划文档）→ 4. **编码与测试** → 5. **迭代开发** → 6. **全面集成测试** → 7. **部署发布**。

### 6.4 代码规范

- **Git 提交**：格式 `类型: 具体描述`；类型含 `feat` / `fix` / `docs` / `style` / `refactor` / `test` / `chore`。
- **文件命名**：小写 + 连字符（`user-profile.js`）；组件用 Pascal（`UserProfile.jsx`）。
- **注释**：关键函数与复杂逻辑必须注释；解释「为什么」而非「是什么」；JSDoc 标注参数与返回值。
- **代码结构**：单一职责；函数一般不超过 50 行；嵌套不超过 3 层。

### 6.5 问题解决机制

同一问题**最多尝试 3 种方案**；失败时详细记录方法与错误，寻找 2–3 条替代路径，必要时质疑基础假设、重新分解问题。

## 7. 分阶段实施路线图（Phase 0–9）

> 每阶段对应 1–3 次课（4 学时/次）。验收统一强调「`npm run dev` 能起 + 接口/测试通过」。

### Phase 0 — 立项与规范（第 1 课）

- **目标**：环境、规范、仓库就绪。
- **关键任务**：安装 Node.js / VS Code / Git；创建 `feynman-platform/backend`；编写统一 `.gitignore`（忽略 `node_modules`、`.env`）与环境变量示例；确定 AI 编程规则与提交规范。
- **交付物**：可运行的 Hello World 服务 + README 初稿。
- **成功标准**：`node index.js` 输出监听日志；浏览器访问 `http://localhost:3000` 返回内容；Git 完成首次提交。
- **测试方案**：手动 curl 验证。

### Phase 1 — 认证与知识点 CRUD（第 2–3 课，讲义已写）

- **目标**：注册/登录/JWT/知识点 CRUD 闭环。
- **关键任务**：接入 MongoDB Atlas；实现 `User` 模型 + bcryptjs 哈希 + 注册 API；JWT 登录 + `middleware/auth.js`；`KnowledgePoint` 模型 + CRUD；补全 `GET /api/knowledge-points/:id`。
- **交付物**：`User` / `KnowledgePoint` 模型 + auth 中间件 + Swagger 初稿。
- **成功标准**：Postman 带 `x-auth-token` 跑通全部 CRUD；无 token 返回 401。
- **测试方案**：Jest 覆盖注册 / 重复邮箱 / 未授权访问。

### Phase 2 — 前端骨架（第 4–5 课）

- **目标**：React + Vite 搭界面，登录/注册/知识点列表联通后端。
- **关键任务**：`npm create vite@latest`；路由；axios 封装（拦截器注入 `x-auth-token`）；Markdown/LaTeX/Mermaid 渲染。
- **交付物**：可登录并增删改查知识点的 Web 应用。
- **成功标准**：浏览器内完成注册→登录→新建→编辑→删除全流程。
- **测试方案**：前端手动联调 + 后端回归测试；处理 CORS。

### Phase 3 — 录音 + ASR 转写（第 6–7 课）

- **目标**：录入知识点 → 录音 → ASR 出文字。
- **关键任务**：前端 `MediaRecorder`；后端 `recordings` 路由 + `Recording` 模型；`utils/asr.js` 统一封装（腾讯云/阿里）；`multer` 处理上传。
- **交付物**：`Recording` 模型 + 转写接口 + 前端录音组件。
- **成功标准**：上传一段录音后，`transcript` 字段被正确填充。
- **测试方案**：单测 mock ASR 返回，断言状态机 `uploaded → done`。

### Phase 4 — AI 润色 / 打分 / 出题（第 8–9 课）

- **目标**：复述文本 → AI 评价 → 薄弱点 → AI 出题 → 入复习计划。
- **关键任务**：`utils/llm.js` 统一封装 + prompt 模板；`AiEvaluation` / `Question` / `ReviewPlan` 模型；SM-2 排期算法。
- **交付物**：评价页 + 题目练习页 + 复习日历雏形。
- **成功标准**：提交复述文本后返回评分与薄弱点，并能据此生成题目与复习计划。
- **测试方案**：Jest mock LLM 返回，断言落库与 `masteringScore` 回写。

### Phase 5 — 知识图谱 2D（第 10–11 课）

- **目标**：图谱可视化与关联维护。
- **关键任务**：`KpRelation` 模型 + `/api/graph`；AntV G6 渲染（力导向、拖拽、缩放、折叠）。
- **交付物**：可交互的 2D 知识图谱。
- **成功标准**：知识点与关系正确呈现，交互流畅。
- **测试方案**：构造固定 `nodes` / `edges`，断言渲染无报错。

### Phase 6 — 3D 知识宇宙（第 12 课）

- **目标**：Three.js + react-three-fiber 把图谱升维为 3D。
- **关键任务**：复用 `/api/graph` 数据；节点球体 + 边连线 + `OrbitControls` + 按掌握度着色。
- **交付物**：可旋转缩放的 3D 知识宇宙。
- **成功标准**：首屏无 WebGL 报错，交互流畅（视觉验收）。
- **测试方案**：视觉验收为主。

### Phase 7 — 跨端打包（第 13–14 课）

- **目标**：Web → PWA → Electron 桌面端。
- **关键任务**：`vite-plugin-pwa` 加 manifest + service worker；Electron 套壳（进阶 Tauri）；monorepo 收口（可选）。
- **交付物**：可安装的 PWA + 桌面安装包。
- **成功标准**：PWA「添加到主屏幕」后离线可用；Electron 启动并能连真实后端。
- **测试方案**：各端分别验证；iOS Safari 特测。

### Phase 8 — 部署上线（第 15 课）

- **目标**：Render 部署后端 + Vercel 部署前端 + Atlas 数据库生产联调。
- **关键任务**：配置环境变量；CORS 指向生产前端域名；`render.yaml`；确认 `.env` 未入库。
- **交付物**：公网可访问的线上平台。
- **成功标准**：生产环境完整跑通「注册→录入→录音→评价→图谱」。
- **测试方案**：生产环境全链路走查。

### Phase 9 — 答辩与复盘（第 16 课）

- **目标**：演示、验收、归档。
- **交付物**：演示视频/幻灯片 + 项目 README + 反思文档。

## 9. 风险与应对

| 风险 | 影响 | 应对措施 |
|---|---|---|
| **AI 服务依赖**（ASR/LLM 限流、欠费、宕机） | 核心流程中断 | `utils/asr.js` / `utils/llm.js` 抽象 + 多供应商可切换；单测用 mock；前端失败友好提示与降级 |
| **国内访问海外云**（Render/Vercel/Atlas 慢） | 演示卡顿 | 备选国内轻量服务器；课堂用本地 `npm run dev` 演示，答辩再上云 |
| **跨域 CORS** | 前端拿不到数据 | 后端 `cors()` 白名单；生产限定前端域名 |
| **MongoDB 连接失败**（IP/白名单/URI 错） | 全站不可用 | Atlas `Network Access` 配置允许访问（教学期 0.0.0.0/0，生产收窄）；`.env` 不入库；启动打印连接状态 |
| **Token 安全** | 越权 / 伪造 | `JWT_SECRET` 强随机且不入库；5h 短有效期；中间件统一校验 `req.user` |
| **跨端适配**（Electron/Tauri WebView 差异、PWA iOS 限制） | 样式/功能不一致 | Web 为主、PWA 次、Electron 套壳最小化原生代码；各端分别验证 |
| **学生基础参差** | 进度断层 | 文档先行 + AI 副驾；每阶段设可运行里程碑；弱基础先跑通 Web，强者做 Tauri/3D 加分 |
| **依赖/版本漂移** | 环境不一致 | `package.json` 锁版本；统一 Node LTS；README 写清安装步骤 |
