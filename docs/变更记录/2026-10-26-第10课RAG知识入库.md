# 第10课：RAG 知识入库

> 这是 2026-10-26 的初始实现记录，当时使用千帆。2026-10-28 已按用户选择切换到硅基流动 `BAAI/bge-m3`；当前配置与验收说明以[切换记录](2026-10-28-第10课切换硅基流动Embedding.md)及后端 README 为准。

## 实施范围

将知识点标题和正文分成最多500个 Unicode 字符一块、相邻块重叠50字符；优先在标点处分块。后端调用百度千帆 Embedding V2 API，使用 Bearer `QIANFAN_API_KEY` 与单独的 `QIANFAN_EMBEDDING_MODEL`（示例 `bge-large-zh`）。不使用讲义旧示例的 AK/SK 签名，也不复用生成模型变量。

使用 `hnswlib-node` 建立 cosine HNSW 索引，每个用户/知识点组合保存一份到被 Git 忽略的 `backend/.data/vector_store/`。目录名由用户和知识点编号的 SHA-256 生成；索引元数据包含归属、内容版本、标题和分块位置。索引先在临时目录完整生成，再替换旧目录。CloudBase 中的知识点仍是正文权威来源，本地索引可重建。

新建、导入、标题/正文更新和版本恢复会在保存后排队索引，后台最多并行2条。状态、分类、标签和复习标记的变化不调用 Embedding；使用独立 `contentRevision` 表示索引对应的正文版本，原 `revision` 继续随所有知识点更新递增。索引失败只写 `failed` 与安全错误码，不撤销已经保存的笔记。新建或内容更新会将分块文本发送给千帆，可能产生调用费用。删除时先保留既有 `deleting` 标记流程，再清理本地索引和复述/测评记录，失败后可重试。

新增认证接口：

- `POST /api/knowledge-points/:id/index`：校验归属并尝试读取本人单条索引；索引当前且可读时返回 `ready`，缺失/过期/损坏时重建。
- `POST /api/knowledge-points/index-all`：为认证用户的全部未删除知识点强制排队重建。

单条接口在现有索引已验证可读且内容版本匹配时返回 HTTP 200 `ready`；否则返回 HTTP 202 `pending` 并排队重建。全部重建返回 HTTP 202，包含每条索引的状态与内容版本。详情和列表增加 `contentRevision`、`vectorIndexStatus`、`vectorIndexedRevision`、`vectorIndexModel`、`vectorIndexErrorCode`。全部重建会产生千帆 Embedding 请求，可能产生费用。

## 手动配置

在被忽略的 `backend/.env` 中填写：

```dotenv
QIANFAN_API_KEY=
QIANFAN_EMBEDDING_MODEL=bge-large-zh
```

把真实值只填写在被忽略的 `backend/.env` 中，不要写入 `.env.example`、前端变量、截图或仓库。Embedding API 与 Key 鉴权依据[千帆 Embedding V2 文档](https://cloud.baidu.com/doc/qianfan-api/s/Fm7u3ropn)和[API Key 鉴权文档](https://cloud.baidu.com/doc/qianfan-api/s/Dmba8k71y)。本次没有发起真实千帆请求。

## 人工验收步骤

配置完成并重启后端后，由用户手动检查：

1. 新建知识点、更新标题/正文、导入知识点、恢复历史版本，确认 `contentRevision` 增加且索引转为 `ready`。
2. 只改状态、分类、标签或复习标记，确认 `contentRevision` 不变、不会再次调用 Embedding。
3. 对本人知识点调用单条重建；对另一用户的编号调用应返回403。全部重建只针对认证用户，并检查每项状态/版本。
4. 删除知识点，确认关联索引目录清理。中断关联清理后再次删除，确认删除流程可以继续。
5. 缺少凭据、供应商超时或服务错误时创建/编辑笔记，确认笔记仍保存，索引变为 `failed`，配置或服务恢复后可以重建。
6. 后端重启后检查本地索引文件保留，并调用单条索引检查确认 HNSW 文件可读取或识别为当前版本。

全部重建会对每条现有知识点强制调用 Embedding，可能产生费用；先确认额度再手动执行。
