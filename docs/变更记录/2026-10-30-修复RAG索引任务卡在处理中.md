# 修复 RAG 索引任务卡在处理中

## 修改内容

- 将索引后台任务的首次 CloudBase 读取放进错误处理范围。读取失败时，任务会尝试把知识点状态更新为 `failed` 并记录安全错误码，避免任务被静默移出队列后仍显示 `pending`。
- 当 CloudBase 因 `pending` 状态未发生变化而返回零条更新时，后台任务会重新读取文档；确认版本仍匹配且状态已是 `pending` 后继续切分和向量化，避免队列紧循环。
- 数据层对索引状态更新采用幂等结果：CloudBase 返回零条更新时复读文档，只有用户、版本和目标字段均匹配才视为成功，避免已就绪索引被误判为待重建。
- 详情页继续轮询索引状态；等待约90秒仍未完成时，提示任务可能已中断，并提供“重新排队”操作。重新排队后会重新启动状态轮询。
- 添加回归测试，模拟后台任务首次读取 CloudBase 失败，以及 CloudBase 报告 `pending` 状态未变化，验证失败状态写回和正常进入索引构建。
- 第6课隔离回归测试改用本地向量替身，避免测试请求真实硅基流动服务。

## 验收范围

- 已运行回归测试和前端生产构建。目标笔记真实 CloudBase + SiliconFlow Embedding 索引成功：6 个分块，`vectorIndexStatus=ready`，`contentRevision=vectorIndexedRevision=5`，并通过本地索引可读性检查；后续单条索引接口返回 HTTP 200/ready；正文未修改。
- 未完成浏览器内的人工页面检查：本机没有可用的 Playwright 模块，Computer Use 无法可靠确认 Edge 当前页 URL，因此按其安全规则停止页面操作。
- 重新排队可恢复已丢失队列任务；任务队列仍为单进程内存队列，暂不提供服务进程启动时自动扫描恢复。
